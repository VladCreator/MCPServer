# P2 - durable automation and private evidence (0.2.0)

Android version 0.2.0/code 12 exposes 37 MCP tools. This release extends the native
runner and agent APIs; it does not require adding these capabilities to YAML.

## Delivered

| Surface | Behavior |
| --- | --- |
| `wait_for_state` | 1-10 `all` predicates share a deadline and active-root sample per poll. Foreground, visible, absent, text and idle reuse native evaluation. Failed conditions, actual values and timestamps are explicit; unstable polls cannot pass. |
| `run_route` | Durable admission before approval/side effects; synchronous compatibility plus explicit asynchronous continuation. Immutable plan digest, dispatch markers, redacted timeline and separately bounded device queue. |
| `get_run`, `cancel_run` | Recover from another approved session using the run ID and recovery key. Cancellation is cooperative; no automatic replay or restart resume. |
| `collect_failure_bundle` | Bounded observation metadata, device state, package/build metadata, filtered log/crash summaries and original failure. Per-source errors retain a partial manifest rather than replacing the primary failure. |
| `export_run`, `get_artifact` | Owned JSON/Markdown report and artifact IDs, never arbitrary file paths. |
| `get_build_identity` | Installed/visible package and version; SHA/CI artifact remain explicitly unknown until the P3 provenance contract. |

Combined waits have a 250-30000 ms shared evaluation deadline and 100-2000 ms
poll interval. Device queue acquisition is separately bounded to 10 seconds.
A successful wait describes an observation, not guaranteed future stability.

## Recovery and consent

See [YAML routes](YAML_ROUTES.md#durable-runs-020) for submission fields. Generate a
cryptographically random, URL-safe `run_key` (32-128 characters) and a stable
`submission_id` before sending an asynchronous or retry-sensitive request.
Only hashed ownership/submission identities and a keyed immutable-plan digest
are persisted. Reusing the same pair returns the retained run; changing the plan
under that pair is rejected.

The recovery key is a bearer capability in addition to an approved MCP session.
Sharing it intentionally delegates access; matching client names grants nothing.
Keep it outside source control and reports. The expanded route approval includes
execution/disconnect and privacy policy, but never displays the recovery key.

Async requires `disconnect_policy: continue_until_terminal`. Request/session
disconnect does not stop accepted execution. Tester stop cancels active jobs;
Android process death leaves unfinished records that become `interrupted` on
the next store open. Dispatched steps become interrupted/outcome-unknown; later
steps are skipped. Neither recovery nor duplicate submission resumes them.

Dispatch persistence precedes each action. That prevents unsafe replay, but does
not prove exactly-once execution across crashes. Cancellation cannot undo an action.
`pending_cleanup` is a warning, not a P3 owned-restoration implementation.
Progress currently uses `get_run` polling, not push notifications.

## Privacy and evidence

Persisted steps retain allowlisted status/reason/timing fields, not YAML,
parameters, selector values, expected/actual free text or tool outputs. Native
history and gateway reports omit private run/evidence arguments and results;
gateway failure details are omitted too. Direct synchronous responses can still
contain approved live UI text.

`privacy_sensitive` defaults to true: route assertion images and bundle screenshots
are suppressed because reliable image masking is unavailable. A non-sensitive
route can return unmasked assertion failure images, as disclosed during approval.
Explicit unmasked bundle images additionally require `include_screenshot:true`
and sensitive-tool consent. Automatic failure bundles remain metadata-only.
Collection must target the package approved for the run; artifacts cannot cross
run ownership even when the caller owns both runs.

Observation evidence removes node text, descriptions, resource IDs, class labels
and references before storage/transmission. Log/crash sources are bounded,
live-target-PID-filtered counts with every message body omitted. Missing READ_LOGS,
no live PID, unsupported historical attribution and source timeouts are explicit.
This intentionally sacrifices diagnostic detail rather than claiming heuristic
redaction is complete.

Sources carry individual timestamps/statuses; the bundle is not atomic.
Unavailable accessibility and protected screenshot capture retain other evidence
and return `isError` for a partial collection. Automatic collection never replaces
the primary route failure. Capture deadlines are cooperative, including Android
framework calls.

Storage limits: 8 active/pending runs, 64 retained runs, 2 MiB per artifact,
20 MiB/256 artifacts total. Terminal records older than 7 days are pruned on new
admission, with their artifacts. Quota errors are explicit, not silent eviction.
Deduplication only applies while the original run remains retained.

## Validation scope

- 73 Kotlin host tests and 16 gateway tests.
- 24 live API 35 contracts: 4 P0, 12 P1 and 8 P2. These cover combined deadlines,
  exact tap-count deduplication, conflicting plans, cross-client ownership,
  cancellation, queue timeout, redacted export, explicit image policy and protected
  capture failure.
- Separate disposable-emulator probes deleted the original MCP session during
  execution and recovered completion with exactly one tap; force-stopped Tester
  after persisted dispatch and recovered the original interrupted run with no
  pending-tap replay; disabled accessibility/log access and retained a partial
  evidence manifest without changing the original run outcome.
- Android/fixture debug builds and lint. Physical-device installation was not
  replaced. This P2 runtime matrix is API 35, not universal/OEM certification.

Saved scenario catalogs/CI reporting remain P4; capability-aware environment
setup, target provenance and crash-safe touched-field restoration remain P3.
