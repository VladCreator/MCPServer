# P1: observation and targeting (0.1.7)

Android versionName 0.1.7 / versionCode 11; MCP and gateway version 0.1.7.
Android advertises 30 tools. iOS's embedded tool subset is unchanged.

## Delivered

- `observe_screen`: tree-only by default, optional window screenshot, capture
  timestamps, hierarchy paths, foreground/window identity, generation, rotation,
  dimensions, truncation and instability. Tree/image capture is not atomic.
- Opaque references bound to the approved client, observation, window generation
  and display geometry. References expire after 30 seconds, same-client observation
  replacement, relevant UI events or successful actions. Revalidation checks the
  live path, node identity and fingerprint. Storage is bounded and memory-only.
- `within` ancestor selectors on native find/check/action tools and YAML steps.
  Click/input/scroll/gesture use one unique-target resolver; ambiguity dispatches
  zero actions unless the caller deliberately chooses `nth`. Removed implicit
  exact-text preference to keep selection semantics consistent.
- Visibility policies and geometry: accessibility-visible, viewport intersection,
  reported clipping, fully-visible reported geometry and advisory actionability.
  Actions default to fully-visible geometry; partially clipped targets require an
  explicit looser policy. Large unrelated clickable ancestors are not a fallback.
- Compose semantic-child input can target the nearest editable ancestor; multiple
  editable descendants remain an error. Field checks still inspect actual text,
  never substitute content descriptions for text.
- WebView accessibility availability is reported without claiming DOM completeness
  or silently guessing coordinates. Window screenshots explicitly fail on
  FLAG_SECURE instead of treating a blank display image as successful evidence.
- Separate `qaFixture` application with synthetic duplicate cards, fields, clipped
  content, Unicode, merged Compose semantics, local WebView and secure window.
  See [`qaFixture/README.md`](../qaFixture/README.md) for reproduction.

## Checks

```bash
./gradlew :shared:testAndroidHostTest :androidApp:assembleDebug :qaFixture:assembleDebug \
  :androidApp:lintDebug :qaFixture:lintDebug --console=plain --quiet
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tools -p test_qa_gateway_mcp.py
```

The host suite covers ownership, expiry, generation/window/rotation/dimension
binding, replacement, storage bounds, schema exposure and scoped YAML compilation,
alongside the P0 regressions. Opt-in native tests are in
`tools/test_android_targeting_mcp.py`; they require a disposable, approved environment.

Verification used an owned API 35 emulator with the separately installed fixture:
66 host tests, 14 gateway tests, four P0 live regressions and 12 P1 live checks
passed. The P1 checks exercised scoped click/input/gesture actions, rejected
ambiguous click/input/scroll/gesture calls with unchanged synthetic data, scoped
route parity, reference-based input/gesture/scroll, tree truncation, optional screenshots, stale/replaced/cross-client
references, actual rotation change and restoration, clipped bounds, Unicode,
Compose semantic-child editing/merged content, WebView accessibility and secure
window image denial. Android and fixture debug builds/lint passed.

Only the disposable emulator was provisioned or installed. The connected physical
device was not modified; this P1 artifact has not been runtime-certified across
API 36/37 or OEM devices.

## Limits

Legacy indices remain process-global and are not safe session-bound references.
Per-call approval UI may itself change the observed window; stale references fail
safely rather than bypassing consent. Android provides no atomic UI-action transaction:
revalidation minimizes, but cannot eliminate, changes between checking and dispatch.

Visibility is based on reported accessibility geometry. Original extent can be
missing/already clipped, transformations can be approximate, and overlays cannot
all be detected. No universal OEM/Compose/WebView support is claimed.
Merged semantics are returned as Android exposes them, not reconstructed.

Android Home/background task policies can delay foreground activation even when
an activity-start request is accepted. A launch readiness timeout remains an
explicit error, not proof that no launch occurred. P1 app-switch checks use an
explicit app-to-app launch; they do not certify every Home/task-transition policy.

Observations are bounded and non-durable; screenshot data is returned, not stored
as a failure bundle. Durable runs/evidence, combined waits and cancellation remain
P2 (0.2.0); setup ownership/recovery remains P3 (0.2.1).
