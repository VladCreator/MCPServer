# P5 - authenticated local run Viewer (0.2.3)

Android version 0.2.3/code 15 retains 43 MCP tools. The selected P5 scope is a
host-side Viewer for existing timeline/artifact APIs, **not continuous recording**.
No new native execution engine, screenshot stream, microphone permission,
MediaProjection service, privileged adapter or iOS tool is added.

## Starting the Viewer

Retain an existing native run's owner-only state file from
[`tester_ci.py`](../tools/tester_ci.py). It must contain `run_id`, `run_key` and
`submission_id`. Obtain an approved native MCP session through the usual
bearer/manual approval flow; a new approved session can recover a run only with
its retained key.

```bash
# Private session/token values belong in the environment, not this command.
export TESTER_MCP_URL=http://127.0.0.1:8080/mcp
python3 tools/tester_viewer.py --state /tmp/tester-attempt-001.json
```

The CLI validates file ownership, owner-only permissions (0600), size and
non-symlink status using the existing CI loader. It validates native run ownership
through `get_run` before opening a listener. It never submits/resubmits a scenario.
Without `TESTER_MCP_SESSION`, the shared MCP client initializes a session using
optional `TESTER_MCP_TOKEN`; normal manual approval applies if no valid token.
HTTPS verifies certificates normally; no insecure TLS option is introduced.
Plain HTTP is permitted only for explicit loopback access such as ADB forwarding.

The CLI prints a loopback URL and a separate random Viewer access token. Open the
URL and paste the token into the password field. The URL itself contains no
token, run key or native session. Treat the token and terminal output as private;
do not upload them to reports or shared CI logs. The Viewer token grants access
to that one retained run and approved existing artifacts, not arbitrary tools.

`--port` defaults to an OS-selected free port; binding is **always 127.0.0.1**.
There is deliberately no `--host`, LAN broadcast, auto-open browser, cloud upload,
external CDN dependency or automatic startup. `--ttl` defaults to 600 seconds
and is bounded to 1-900; expiry revokes the token and stops the server.
Ctrl-C also revokes access and closes the listener.

## Native data, no competing reports

The page shows the exact redacted native run/step IDs, phase, status, offsets,
duration, primary/cleanup result and pending restoration flags. It polls
`get_run` once per second only while the run is active, without overlapping
browser requests. Terminal runs stop polling. Failed transport/native requests
pause polling visibly and are never silently retried. Refresh and Pause/Resume
are explicit. A fetched snapshot is not a live screen or guarantee of UI state.

JSON, Markdown and JUnit download buttons call the existing owned `export_run`.
Downloads are the bounded canonical native content, not host-reconstructed
verdicts. The host caches at most one export snapshot per format, keyed by native
run content, to avoid repeatedly consuming native artifact quota for unchanged
reports. The native store's existing quotas/retention still apply.

An explicit existing artifact-ID download calls native `get_artifact` with the
same retained owner. Native approval still applies when enabled, including
unmasked images previously admitted/captured under the run's policy.
The Viewer cannot collect new evidence, bypass `FLAG_SECURE`, take observations,
launch/control apps or access arbitrary paths/URLs. Text is downloaded as plain
text and JPEGs as attachments; the page never interprets artifact HTML.
Copy an existing ID from a native manifest/run response; there is no global
artifact listing, cross-run browse, capture button or screenshot polling.

The gateway continues referencing the same native IDs; Viewer reads do not create
a second QA session/report. `get_capabilities.visibility` identifies the Viewer
as optional **host execution**, with recording/live/microphone capture unsupported.

## Access lifecycle and browser boundaries

All data and control endpoints require the separate Viewer Bearer token in the
Authorization header on **every request**. Only the static page/script/style are
public, and they contain no run data or secrets. Tokens are held only in browser
memory, never cookies, URLs, browser storage or script source. The run recovery
key, backend bearer/session and state-file path stay on the host.

Requests require the exact loopback Host/port; foreign Origin and cross-site
fetch requests are rejected. No CORS access is granted. Responses use no-store,
nosniff, no-referrer and a self-only content policy forbidding framing, external
scripts and HTML injection. DOM text uses `textContent`, not `innerHTML`.
Requests with bodies/transfer encoding are rejected. The server bounds concurrent
connections (four), header/socket waits and upstream response/artifact sizes;
upstream calls are serialized and never automatically replayed.

**Revoke access** invalidates the process token, clears the host export cache and
the current page's data/token. It cannot be reauthorized without restarting the
Viewer. It leaves only an unauthenticated static shell listening until TTL expiry
or Ctrl-C. **Stop Viewer** revokes and closes the listener immediately.
Authenticated POST is required; GET links cannot revoke or stop it.
Responses still in flight when revocation is observed are discarded before
delivery. Bytes already delivered/downloaded cannot be recalled or deleted from
another browser tab.

Neither control cancels the native run, undoes actions, revokes its recovery key,
restores device state or deletes native artifacts. Use existing native
`cancel_run`/`device_state` recovery separately with explicit authority.
The Viewer does not own the native session; stopping it does not DELETE a session
that another agent/CI client may be sharing.

Loopback authentication protects against unauthenticated local web requests,
not a malicious process running as the same OS user, browser extensions or
compromised native servers. Existing native approval and privacy rules remain the
source of authority. Do not expose the port through tunnels/proxies or share the
access token; there is no multi-user access-control claim.

## Verification and deferred work

Automated contracts cover loopback binding, per-request auth, Host/Origin checks,
native key scoping, canonical downloads/cache, explicit artifact consent,
bounded content, expiry, revoke/stop, in-flight response discard and real HTTP
MCP request shape. The static client has no persistent token storage, HTML
interpretation or capture endpoints.

Release validation passed 102 Kotlin host tests, 16 Viewer HTTP/ownership tests,
8 JavaScript DOM/lifecycle tests, 8 CI-client tests and 19 gateway tests.
The Android debug build and lint passed. On the isolated API 35 emulator,
3 reusable native Viewer integration cases and the 4 native predicate/capability
regressions passed. A separate actual CLI probe fetched an accepted native run,
downloaded all three canonical formats and an explicitly approved existing
artifact, then verified revoke, stop and TTL expiry without replaying/cancelling
the native run or capturing new evidence. Physical-device/OEM/browser-wide
certification is not implied by emulator and mocked-DOM coverage.

Run host checks with:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tools -p 'test_tester_*.py'
node --test tools/test_viewer_ui.cjs
```

The opt-in [`test_android_viewer_mcp.py`](../tools/test_android_viewer_mcp.py)
uses `TESTER_VIEWER_STATE`, `TESTER_MCP_URL` and `TESTER_MCP_SESSION` for one
already accepted owned run. It does not submit actions or bypass consent.

Continuous screen recording/live video, on-demand new observations from the
Viewer, microphone capture, privileged permission/location/time adapters and a
public/LAN Viewer are explicitly deferred. Future recording needs separate
per-run approval, any required Android OS authorization, a visible indicator,
bounded retention and secure-content restrictions; this release does not claim
those requirements have been implemented.
